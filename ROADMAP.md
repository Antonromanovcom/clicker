# Roadmap разработки Awake

## Цель

Создать Java CLI-утилиту с двумя независимыми режимами: системным `inhibit` без эмуляции ввода и безопасным `activity` для явно заданного приложения или временного файла.

## Этап 1. Основа CLI — готово

- [x] Реализован собственный parser без runtime-зависимостей.
- [x] Добавлены `--help` и `--version`.
- [x] Добавлены `--mode`, `--hours`, `--from`, `--until`, `--target`, `--interval`.
- [x] Добавлена проверка несовместимых, повторяющихся и отсутствующих параметров.
- [x] Зафиксированы exit codes: `0`, `2`, `3`, `130`.
- [x] Добавлены unit-тесты parser и точки входа.

CLI принимает конфигурацию и запускает безопасную заглушку выбранного режима. Реального воздействия на систему пока нет.

## Этап 2. Планировщик времени и жизненный цикл

- Преобразовать `--hours`, `--from` и `--until` в единое окно выполнения.
- Определить поведение интервалов через полночь.
- Использовать монотонный таймер для длительности.
- Добавить ожидание старта, штатное завершение и обработку `Ctrl+C`.
- Покрыть расчёты времени тестами.

## Этап 3. Контракт режимов

- Ввести общий интерфейс `start`/`stop`.
- Отделить CLI и планировщик от платформенных реализаций.
- Добавить определение macOS, Windows и Linux.
- Сделать повторную остановку безопасной.

## Этап 4. Режим `inhibit`

- macOS: управлять дочерним процессом `caffeinate`.
- Windows: использовать системный Power API, вероятно через JNA.
- Linux: сначала поддержать `systemd-inhibit`, затем при необходимости D-Bus.
- Всегда освобождать системную блокировку при завершении и ошибках.

## Этап 5. Проектирование безопасного `activity`

- Всегда требовать `--target`.
- Не отправлять ввод вслепую в текущее активное окно.
- Проверять процесс и окно цели перед каждым действием.
- При потере цели приостанавливать активность.
- Добавить аварийную остановку и `--dry-run`.
- Зафиксировать модель угроз и ограничения поддерживаемых редакторов.

## Этап 6. Режим `activity`

- Разделить поиск цели и генерацию действия.
- Для файла использовать отдельный временный рабочий файл.
- Реализовать обратимое действие и проверку неизменности содержимого.
- Возвращать фокус исходному окну только там, где это надёжно.
- Начать с одной платформы и одного редактора.

## Этап 7. Надёжность

- Добавить уровни журналирования.
- Проверить закрытие цели, блокировку экрана и завершение терминала.
- Исключить несколько экземпляров для одной цели.
- Документировать необходимые системные разрешения.

## Этап 8. Доставка

- Настроить CI для Java 11/17/21 и поддерживаемых ОС.
- Подготовить checksums и инструкции установки.
- После стабилизации рассмотреть нативные пакеты через `jpackage`.
