# Roadmap разработки Awake

## Цель

Создать Java CLI-утилиту с двумя независимыми режимами: системным `inhibit` без эмуляции ввода и безопасным `activity` для явно заданного приложения или временного файла.

## Этап 1. Основа CLI — готово

- [x] Реализован собственный parser без runtime-зависимостей.
- [x] Добавлены `--help` и `--version`.
- [x] Добавлены `--mode`, `--hours`, `--from`, `--until`, `--target`, `--keypress-interval` (и совместимый псевдоним `--interval`).
- [x] Добавлена проверка несовместимых, повторяющихся и отсутствующих параметров.
- [x] Зафиксированы exit codes: `0`, `2`, `3`, `130`.
- [x] Добавлены unit-тесты parser и точки входа.

CLI принимает конфигурацию и запускает безопасную заглушку выбранного режима. Реального воздействия на систему пока нет.

## Этап 2. Планировщик времени и жизненный цикл — готово

- [x] `--hours`, `--from` и `--until` преобразуются в единое окно выполнения.
- [x] Прошедшее время `--until` означает следующий день; окончание до `--from` означает переход через полночь.
- [x] После старта длительность отсчитывается монотонными часами.
- [x] Добавлены ожидание старта, штатное завершение и обработка `Ctrl+C`.
- [x] В консоли отображаются режим, старт, окончание и причина завершения.
- [x] Расчёты покрыты тестами, включая полночь и переход на летнее время.

## Этап 3. Контракт режимов — готово

- [x] Введён общий интерфейс режима: описание, `start`, `stop` и состояние.
- [x] CLI и планировщик отделены от конкретных реализаций режимов.
- [x] Добавлены фабрика режимов и определение macOS, Windows и Linux.
- [x] Неизвестная платформа завершается с кодом `3`.
- [x] Остановка режима идемпотентна и вызывается при штатном завершении, ошибке и остановке JVM.
- [x] На этом этапе оба режима были представлены безопасными заглушками.

## Этап 4. Режим `inhibit` — готово

- [x] macOS: управление отдельным процессом `/usr/bin/caffeinate -i`.
- [x] Windows: системный `SetThreadExecutionState` через JNA на выделенном потоке.
- [x] Linux: отдельный процесс `systemd-inhibit` с блокировкой `idle:sleep`.
- [x] Немедленно завершившийся backend считается ошибкой запуска.
- [x] Системная блокировка освобождается при штатном завершении, ошибке и остановке JVM.
- [x] Сон дисплея намеренно не блокируется.

## Этап 5. Проектирование безопасного `activity` — готово

- [x] `activity` всегда требует `--target`.
- [x] Добавлен `--no-inhibit`; без него activity включает системный inhibit как страховку.
- [x] Добавлен `--erase-after N` с пределом 1000 символов.
- [x] Добавлен `--dry-run` без системных эффектов.
- [x] Зафиксированы повторная проверка цели, приостановка при потере окна и правила очистки остатка.
- [x] Модель угроз и ограничения описаны в `ACTIVITY-SAFETY.md`.

## Этап 6. Режим `activity` — готово для Windows Notepad, macOS TextEdit и Linux/X11

- [x] Планировщик вызывает `pulse()` режима с заданным `--keypress-interval`.
- [x] Реализация для macOS поддерживает TextEdit.
- [x] Исходный `--target` не изменяется; используется отдельный временный документ.
- [x] Перед каждым действием проверяются приложение, документ и ожидаемая длина.
- [x] Ввод подтверждается чтением состояния только временного документа.
- [x] `--erase-after N` удаляет подтверждённую партию и проверяет нулевую длину.
- [x] При завершении документ закрывается без сохранения, временный файл удаляется.
- [x] Фокус возвращается предыдущему приложению; конфликт с другим окном TextEdit приводит к пропуску действия.
- [x] Windows: основной backend для явно заданного `notepad.exe`, с проверкой PID окна и сохранённого временного файла.
- [x] Linux: backend для X11 через `xdotool`, с проверкой PID окна и сохранённого временного файла.
- [x] Добавлена CI-сборка на Windows, Linux и macOS для Java 11/17/21.
- [ ] Провести нативную ручную проверку Windows-ввода на целевом компьютере.
- [ ] Добавить Wayland и другие Windows-редакторы отдельными расширениями.

## Этап 7. Надёжность — готово

- [x] Добавлены уровни `quiet`, `normal` и `verbose` через `--log-level`.
- [x] Путь target, заголовки окон и содержимое документа не попадают в журнал.
- [x] Добавлена межпроцессная блокировка: одну цель нельзя одновременно использовать в двух экземплярах Awake.
- [x] При ошибке запуска второй части composite-режима уже запущенная часть откатывается.
- [x] Закрытие временного документа или изменение его содержимого приводит к безопасной ошибке и очистке.
- [x] `Ctrl+C` и завершение JVM останавливают режим через shutdown hook.
- [x] Разрешения и ограничения платформ описаны в `PERMISSIONS.md`.
